## 它解决什么问题

电商页面上的信息是**分层**的：参数卡只有商家愿意填的字段，配料表、材质成分、执行标准原文通常压在详情长图的最后几张，再往下还得问客服。AI 往往翻到第一层就停手，回一句「查不到」，然后凭价格给建议。

这个项目把「**信息没查全不许下结论**」做成两件东西：

| 组成 | 作用 |
| --- | --- |
| **技能**（`pick-goods`） | 真正起作用的部分。把四层信息漏斗、六张品类核验表、标准号事实卡、客服话术固化给 AI，让它在你说「帮我挑个 X」时按同一套流程走。 |
| **插件**（`local-pick-goods`） | 让它顺手。把方法论做成手机上能翻能点的原生面板，点一下就变成一段发给 AI 的请求。 |

两者独立可用：只装技能也能生效；装上插件，则多出三个面板和两个加号工具。

## 安装

### 方式一：让 AI 帮你装

不用手敲任何命令。在 [dsh-go](https://github.com/ccch1mneyyy/dsh-Go) 里新开一个对话，把下面这段原话发给它：

> 帮我装这个 dsh-go 插件：https://github.com/melosic/dsh-go-pick-goods
> 装到 `$DSH_HOME/dsh-go/plugins/` 和 `$DSH_HOME/skills/`，装完告诉我怎么重启引擎。

它会克隆仓库、执行 `install.sh`、把插件注册进当前 profile。最后一步「重启引擎」需要你自己操作。

### 方式二：手动执行命令

```sh
git clone https://github.com/melosic/dsh-go-pick-goods.git
cd dsh-go-pick-goods
sh install.sh
```

脚本会做三件事：把插件复制到 `$DSH_HOME/dsh-go/plugins/local-pick-goods`、把技能复制到 `$DSH_HOME/skills/pick-goods/`、把插件注册进当前 profile。

### 装完之后

到 **[dsh-go](https://github.com/ccch1mneyyy/dsh-Go) → 设置 → 引擎 → 重启引擎**，面板才会出现。

## 使用

### 三个面板

**选品参谋**（输入框上方「插件」弹层）—— 只放入口，不摆正文：四个按钮分别是「选品手册」「标准号速查」（跳转面板）和「开始选品」「验一下已有商品」（把完整请求塞进输入框）。

**选品手册**（全部功能 → 选品手册）—— 照着做就不会漏：

- **第 0 步：在哪个平台买。** 六个平台按钮分两行，点一下就把「就在这个平台买 + 这个平台要特别当心什么」塞进输入框
- **四层信息漏斗**：参数卡 → 客服 → 详情长图 → 评价。客服要最先问出去（先发商品卡片，再提问），边等回复边翻长图，两条线并行
- **六个品类按钮**：食品 / 电器 / 服装 / 化妆 / 家居 / 母婴，点一下列出该品类必须核验的项
- **客服话术四条**：要包装图、兜底问法、客服打太极时怎么接、要铭牌和 3C
- **营销话术对照表** + **到手价公式**
- **结论怎么画**：一张「品类 → 比什么 → 怎么画」的对照表

**标准号速查**（全部功能 → 标准号速查）—— 报标准号之前先看这张表：

- 食品 16 条：灭菌乳 / 巴氏乳 / A2 / 婴配粉 / 大米 / 植物油 / 酱油 / 食醋 / 蜂蜜 / 饮用水 / 标签 / 营养标签 / 食品添加剂 / 生产卫生 / 标识监管 / 委托生产
- 电器、纺织、玩具、化妆品、家居、母婴、宠物 14 条：GB 44246-2024、CCC 目录、GB 18401、GB 6675-2025 玩具、GB 28007-2024 儿童家具、GB 18580-2025 人造板、GB 7916-2026 化妆品等
- 8 个官方查询入口：国标全文、食品安全国标、婴配粉注册、CCC 证书、能效备案、化妆品备案、企业信用、团体标准
- 八条「警戒线」：**「发布」不等于「生效」**、哪些版本已经废止、哪些看起来像标准号的词其实没有国标撑腰

每条都带**状态列**（现行 / 待实施 / 推荐性）和**实施日期**，避免把「已发布未生效」的新规当成现行去判旧货。

> 面板里的按钮都只做一件事：把文字放进输入框，**不会自动发送**——你可以先改再发。

### 技能

`skill/pick-goods/SKILL.md` 放进 `$DSH_HOME/skills/pick-goods/` 后会被自动发现，不需要注册。

之后你说「帮我挑个吹风机」「这个靠谱吗」「比一下这几个」，AI 会走同一条流程：

**确认平台 → 需求五问 → 拉 3 个候选（覆盖三个价位）→ 四层信息漏斗 → 品类核验 → 到手价 / 单位价 → 营销话术体检 → 带出处的结论 → 画成图**

---

## 方法论

八条核心，缺一条结论就不可靠：

1. **先确认平台，别默认。** 同一个东西在不同平台能差 20%+，闷头默认一个就是替用户做决定。
2. **参数卡永远没有配料表 / 材质成分 / 执行标准原文。** 那是模板字段，指望不上。
3. **客服最先问出去，别等。** 进客服先发商品卡片，客服才知道你问的是哪个链接、哪一版规格；再打字提问，然后立刻去翻长图，等回复的时间正好用来翻。
4. **问客服要具体，问完必须回访。** 别问「有配料表吗」（客服会顺手回「没有」），要问「能发一下包装背面的产品信息图吗」。
5. **详情页必须滑到底。** 产品信息块通常在倒数 1～3 张长图里。
6. **结论必须带证据。** 每条理由后面跟出处：参数卡 / 客服原话 / 详情第几张图 / 哪条评价。说不出出处就是猜。
7. **不替用户拍板超预算的东西。**
8. **结论要一眼看完。** 先定可比单位再画图——牛奶比每升、电视比功率和年电费；能一句话说清的就别画。

结论固定带着一段「**没查到**」：哪项信息缺失、为此做了什么、结果如何。决策依据的边界，和推荐本身一样重要。

## 一个完整的例子

> **你**：帮我挑一箱纯牛奶，A2 的，别太贵。

AI 的动作大致是：

1. **确认平台**——你说拼多多，就按拼多多的路径走
2. **需求五问**——喝多久、能否装箱、价格上限、能否接受临期
3. **拉候选**——三个不同价位的 A2 牛奶
4. **四层漏斗**——参数卡只有生产日期和蛋白质；先开客服，把商品卡片和问题一起发过去要包装背面图，一边等一边翻详情长图倒数几张的「产品信息」小表格
5. **核验**——产品种类是不是「灭菌乳」、执行标准是不是 GB 25190、配料表里有没有复原乳
6. **算到手价**——扣掉券和满减、加上运费，再除以总毫升数得到每 100ml 单价
7. **给结论**——推荐 + 理由（带出处）+ 风险 + 备选 + 没查到的那一段，并配一张横条图比单位价

全程不会自动下单，也不会碰支付。

## 项目结构

```
.
├── package.json                 # 插件清单：dshGo 声明（面板、工具、图标）
├── cordis.patch.yml             # 让引擎加载本插件
├── lib/index.js                 # 面板视图与点按处理
├── skill/pick-goods/SKILL.md    # 选品方法论技能
├── install.sh                   # 一键安装
└── README.md
```

改 `lib/index.js` 之后，需要在 App 的「引擎」页重启引擎才会生效；改 `package.json` 会自动重读。

## 非目标

这个项目**不做**下面这些，是有意为之：

- **不自动下单、不碰支付与验证码。** 插件只读页面信息、只往输入框里写文字，最后一步永远由用户自己点。
- **不做比价爬虫。** 平台数据受反爬和动态价影响，抓来的数字往往比手动核对更不可信。
- **不建商品库。** 商品会下架、会改价，固化的应该是方法，不是库存。
- **不替你拍板。** 超预算、有硬伤的商品一律不给推荐，只给事实。

## 常见问题

**面板没出现？**
先确认引擎已重启，再检查 `$DSH_HOME/dsh-go/plugins/local-pick-goods` 目录是否完整（`package.json`、`cordis.patch.yml`、`lib/index.js` 三件套）。

**点了按钮，输入框里有文字但没发出去？**
这是设计如此。所有按钮只做插入，不会替你发送——请求里的商品名、平台、品类都可以先改。

**标准号表会不会过期？**
面板里的数据是 2026-11-07 的快照。标准号会更新、新规会分批实施，隔上几个月再用之前，请以面板底部列出的官方入口复核一遍。

**技能和插件必须一起装吗？**
不必。技能负责方法，插件负责顺手；只装技能也会生效，只是要自己记住流程。
