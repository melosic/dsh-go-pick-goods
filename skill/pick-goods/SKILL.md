# 网购选品方法论

一句话：**把「买什么」拆成可验证的验收标准，用四层漏斗把信息查全，再用单位价和人话结论收尾。**

最容易犯的错不是选错，是**信息没查就下结论**。看完参数卡说「找不到配料表」然后退出，等于什么都没做。

---

## 铁律（破任意一条，这次选品就算失败）

1. **动手前先确认在哪个平台买。** 同一个东西不同平台差 20%+，闷头默认一个平台等于替用户做了决定。用户没说就先问一句。
2. **不许说「找不到」就结束。** 信息一定在下面四层里的某一层，逐层往下找，找到底为止。
3. **参数卡不等于全部信息。** 电商参数卡是商家自己填的模板，字段固定且有缺项，**永远不包含配料表、材质成分、执行标准原文**。这些要么问客服要，要么在详情长图里。
4. **客服要最先问出去，不要等。** 问客服只花十几秒，翻详情长图要一张张滑、还要放大看小字。**先发商品卡片说明问的是哪一款，再打字提问，发完立刻去翻长图**，等回复的时间正好用来翻，两条线并行。
5. **问客服要具体，问完必须回访。** 客服经常先糊弄一句「没有呢」，追问才给。
6. **客服回复了必须回去看。** 发完问题不是任务结束，是任务开始。
7. **详情页咬牙看完最后几张，但最多滑 6 次。** 重点是长图里的「产品信息」「产品参数」「执行标准」「配料」「成分」「厂名厂址」，通常在**倒数第 1～3 张图**。滑了 6 次还没出现，直接转客服要图，别为了这个商品一直往下翻。
8. **结论必须带证据。** 每个推荐理由后面跟一句出处（参数卡 / 客服原话 / 详情图第几张 / 哪个评价）。说不出出处的判断就是猜。
9. **不替用户拍板超预算的东西。** 给 2～3 个方案 + 取舍理由，让用户选。
10. **有时间纪律。** 整个选品 3～5 分钟内给结论。结果页只读第一屏、详情页最多滑 6 次、客服发完问题不干等。发现自己滑了 10 屏还没选，就是方向错了，立刻回头从第一屏挑。

## 第 0 步：把模糊需求变成验收标准

用户说「帮我挑个 X」，先在心里补全这五个空（缺的用常识默认，**只问真正影响结果的**，别一次抛五个问题）：

| 维度 | 要问清 / 默认值 |
|---|---|
| 用途 | 自己用 / 送人 / 老人小孩 / 商用，决定优先级完全不同 |
| 硬约束 | 预算上限、尺寸、口味忌口、过敏原、必须的功能 |
| 可妥协 | 品牌、外观、包装、发货速度 |
| 数量与周期 | 一次买多少、多久回购一次 → 决定买大包装还是小包装 |
| 失败的代价 | 买错了是浪费几十块还是几百块 → 决定要不要多花时间查证 |

**先给一句「我按这个理解来找」再动手**，用户一句话就能纠正，比找错方向省事。

---

## 第 0.5 步：先确认在哪个平台买（别默认）

同一个商品在不同平台的到手价能差 20% 以上，售后、发货、真假风险也完全不同。**没确认平台就开始翻商品，等于替用户做了个他没同意的决定。**

### 怎么问

**一步问清，别连问三轮。** 先动手查本机装了哪些购物 App，再只把装了的列给用户选：

```
mcp__phone__apps(query: "拼多多")   // 或直接不带参数列全部
```

然后一句话问：

> 「这次在哪个平台买？（本机装了：拼多多 / 闲鱼 / 抖音；淘宝、京东、1688 没装）」

- 用户回了平台 → 直接用，别再啰嗦。
- 用户说「你看着办 / 都行」→ 按下方默认规则选**一个**，并说一句为什么选它，然后继续。
- 用户要的平台本机没装 → 说明情况，给两个选项：装一个 / 改用浏览器（`open(url:)`）或者反过来换个平台。

### 什么时候不用问

- 用户自己点名了平台（「拼多多上帮我看看」「京东有没有」）。
- 用户直接甩了一个商品链接或截图——链接的域名就是平台，跟着走就行。
- 纯咨询「这东西一般多少钱」这类不需要真去翻页面的问题。

### 默认规则（用户说「随便」时用）

| 买什么 | 默认去哪 | 理由 |
|---|---|---|
| 日用百货、生鲜、小件、白牌能接受 | 拼多多 | 最便宜，但要按下面的要点查得更狠 |
| 电器、数码、大件、售后要紧 | 京东（自营） | 自营售后省心，贵的那点值 |
| 衣服、家居、品类杂、要比款 | 淘宝 / 天猫 | 款式全，尺码颜色选择多 |
| 囤货、批发、同款大量 | 1688 | 单价低，注意起订量和是否含税 |
| 二手、停产款、捡漏 | 闲鱼 | 便宜，但必须走平台交易 |
| 直播间看到、冲动价 | 抖音 / 快手 | 先确认能不能开发票、支不支持 7 天无理由 |

**大件（>500 元）或差价敏感的，跨平台比一遍再下结论**，至少比两个。

## 第 1 步：拉候选池

**只在第一屏选，最多滑一次。** 搜索结果页是个陷阱：越往下越便宜，但销量和质量断崖式下跌，而且每多滑一屏就要多花几十秒。/ 规则是——

- **默认只看搜索结果第一屏**（通常 4～8 个商品）。第一屏基本就是平台按「销量 × 转化」排的，最有代表性。
- 第一屏凑不出 3 个覆盖不同价位的，**才允许滑一次**（到第二屏），滑完就停。
- **绝不连续滑两屏以上**找一个「更便宜的」。多滑的那两屏时间比省下的几块钱贵得多。
- 想按价格排序就直接点「价格」筛选，**不要靠滑屏找**。
- 每个候选点进去**只做四层漏斗，不逛店铺**（不点「进店看看」「相似推荐」「猜你喜欢」，那是无底洞）。

**候选怎么定**：至少 **3 个候选**，覆盖三个价位段（低价、中位、高价），否则没法判断性价比曲线。**第一屏不够就放宽价位，不是放宽滑屏深度。**

**先把候选池报出来，再点进去。** 第一屏 `screen` 读完，先用**一句话**告诉用户你选了哪几个、为什么，再开始逐个点进去查。例如：

> 第一屏 6 个，我挑这 3 个：辉山奢享 ¥19.7（品牌旗舰）、塞北牧乡 ¥23.9（蛋白最高）、牛等等 ¥30.5（最贵，做对照）。开始查参数了。

这一步是给用户**否决权**——他可能一眼就说「第一个我买过不好喝，换一个」。省下你查完三个才发现白忙。别跳过，别等查完再说。

- 同一商品在不同平台的到手价能差 20%+，大件建议跨平台比（跨平台也要各自的**第一屏**，不是每个平台滑到底）。
- 排序别只看「销量」：销量高可能是刷的或者低价引流，看**「已拼 / 已售 + 评价数 + 店铺评分」三件套**是否对得上。
- 页面筛选项能省很多事：先按「销量 / 价格区间 / 发货地 / 品牌」过滤一遍再逐个看。

## 第 2 步：信息补全四层漏斗（核心）

**顺序很重要：客服找的是 L2，不是 L3。** 问客服只花十几秒，翻长图要一张张滑、还要放大看小字。所以参数卡看完就先发问，**发完立刻去翻长图，别干等回复**。

### L1 商品页参数卡 / SKU 规格

商家填的结构化字段。**只用来快速筛掉明显不合适的，不用于下结论。**

- 记下能拿到的：价格、规格（净含量 × 数量）、生产日期 / 保质期、关键数值指标、店铺名。
- 参数卡缺什么，就是接下来要找什么——**先列出缺口清单**。

### L2 客服（先发问，再干别的）

**先发问。** 缺口清单一列出来，第一件事就是点开客服把问题发出去，然后再回来翻长图——**等回复的这几分钟正好用来翻，两条线并行，不浪费**。

**进客服先发商品卡片。** 一个店常挂几十上百个 SKU，光打字说「A2 纯牛奶」客服不知道你问哪一款。点开客服窗口后，先点**右下角浮着的商品卡片**（拼多多叫「点击发送该商品」；淘宝/天猫是底部商品条，京东是「发送当前商品」，抖音是「发送商品」），**先把这件货发过去**，再打字提问。卡片发送后客服那边能看到确切链接，回复准确率明显高一截。

- 有的 App 卡片是自动置灰或要长按，找不到就**手动把商品标题 + 规格全称**打一遍。
- 卡片发出去后聊天框顶部会显示这件商品，确认是**你要问的那一版规格**（同一款有 250mL×10 / 200mL×12，别发错）。
- 已经被客服换了会话窗口的话，重进商品页再点一次客服，卡片会重新浮出来。

**问法很重要。** 别问「有配料表吗」（客服会顺手回「没有」），直接要**具体的东西**：

- 食品/日化：`麻烦发一下包装背面的产品信息图（配料表 + 执行标准 + 生产许可证那面），谢谢`
- 服装：`这件的水洗标成分是什么？吊牌执行标准和安全类别（A/B/C）是多少？`
- 电器：`这台机器的铭牌参数图和 3C 认证编号能发一下吗？`
- 家居：`板材的甲醛释放限量等级和检测报告能发一下吗？`
- 通用兜底：`商品详情里没找到 XXX，能发一下包装实拍图吗？`

**流程**：商品页底部「客服」→ **先点右下角商品卡片，把商品发过去** → 输入框打字 → 有的平台打完还要再点一次「发送」→ **发完立刻去翻长图（L3）** → 翻完回来看回复 → 答非所问就换个问法追问（追问「我要的是包装背面的图，麻烦拍一下」通常有效）。

**客服常见挡箭牌和应对**：

| 客服说 | 什么意思 | 怎么办 |
|---|---|---|
| 「详情页都有的哦」 | 让你自己去翻 | 回「详情页我翻完了，没看到配料表，麻烦发图」 |
| 「暂时没有呢」 | 懒，或者真没有 | 换问法：要「包装图」不要「配料表」 |
| 「以实物为准」 | 不想给 | 说明是买之前确认，要下单前确认，态度坚定但客气 |
| 给了别的产品的图 | 发错 | 指出具体商品名再要一次 |

### L3 详情长图（客服在等回复时，正好翻这个）

页面往下滑到「商品详情」，图片一张张翻。要找的关键词：

> 产品信息 · 产品参数 · 产品规格 · 执行标准 · 配料 · 配料表 · 成分 · 主要原料 · 材质 · 面料成分 · 厂名厂址 · 生产许可证 · SC 号 · 注意事项

- 这类信息通常在**倒数 1～3 张图**，做成一张小表格的样子。
- 看不清就把图放大 / 截图后放大看；图上文字小是常态。
- **翻完先看客服回了没**：回了就核对，没回就再追问一句或者直接去评价区。
- 翻了三张还是看不出所以然，别死磕——客服那边基本会有，先看回复。

### L4 评价 / 问大家 / 追评

- **「问大家」比评价有用**：是真人在答具体问题，能问到「是不是正品」「生产日期新鲜吗」。
- 追评看**长期使用**问题，首评多半是收货当天情绪。
- 差评别只看分数，看**差评的具体理由**：如果是「包装破了」可接受，「有异味」「假的」就要警惕。
- 中评区往往是真话最多的地方。

## 第 3 步：按品类核验关键参数

每个品类都有「不看这个就白买」的指标。**在不知道品类关键指标时，先查下面这张表再动手。**

### 食品 / 生鲜 / 饮品

| 要查 | 为什么 |
|---|---|
| **配料表**（按含量降序） | 判断是不是「纯的」、有没有加糖/香精/植脂末、添加剂多不多 |
| 产品种类 / 分类 | 如「灭菌乳」vs「调制乳」vs「含乳饮料」是完全不同的东西，价格差几倍 |
| 执行标准号 | 能反查是不是按这个品类做的，营销词没有标准号支撑就是话术 |
| 生产日期 / 保质期 | 短保的要看发货地和物流天数 |
| 营养成分表（每 100g / NRV%） | 注意单位陷阱：有的标「每份」不是「每 100g」 |
| SC 号（食品生产许可证） | 能查生产商是否真实存在、资质是否匹配 |
| 净含量 vs 规格 | 「200ml×10 盒」和「2L 一箱」要换算成**每 100ml 单价**再比 |

### 电器 / 3C / 数码

| 要查 | 为什么 |
|---|---|
| 3C 认证（CCC）编号 | 强制认证目录内的产品必须有，编号可查 |
| 额定功率 / 容量 / 尺寸 | 注意「额定」不等于「峰值」，虚标很常见 |
| 能效等级 | 长期用电成本可能超过差价 |
| 保修期 + 是否全国联保 | 店铺保修 vs 品牌保修差很多 |
| 型号后缀 | 电商专供型号常减配（少接口、缩水散热），要和官方型号逐项对 |

### 服装 / 鞋 / 纺织

| 要查 | 为什么 |
|---|---|
| 面料成分比例 | 「纯棉」「羊毛」有法定含义，含量不足不能这么叫 |
| 安全类别 A/B/C | A 婴幼儿、B 直接接触皮肤、C 非直接接触，贴身穿必须 B 类以上 |
| 执行标准 + 吊牌 | 正规品有吊牌，无吊牌多为尾单/仿品 |
| 尺码表 + 版型 | 看实测数据不是看 S/M/L |

### 化妆品 / 日化

| 要查 | 为什么 |
|---|---|
| 全成分表（按含量降序） | 判断有效成分是否有、浓度是否靠前 |
| 备案号 / 注册证号 | 国产普通化妆品有备案号，可查，无备案就是三无 |
| 保质期 + 开封后使用期 | 临期货便宜但有风险 |
| 功效宣称 | 「美白」「防晒」「防脱」属特殊化妆品，必须有特证 |

### 家居 / 建材 / 家具

| 要查 | 为什么 |
|---|---|
| 板材甲醛释放限量等级 | 室内用人造板有强制限量，等级差一档差别很大 |
| 实木 vs 实木多层 vs 颗粒板 | 「实木」两个字被滥用，「实木颗粒板」其实是颗粒板 |
| 尺寸与承重 | 量好门洞/电梯/楼梯再买大件 |
| 安装费 / 运费 / 上楼费 | 大件隐藏成本常占总价 10～20% |

### 母婴 / 宠物 / 保健

| 要查 | 为什么 |
|---|---|
| 适用年龄 / 段位 | 婴配粉分段有强制要求，跨段不合适 |
| 配方注册号 | 婴配粉必须有注册号，可查 |
| 成分禁忌 | 宠物食品看是否有对特定品种有害的成分 |
| 保健食品「蓝帽子」标志 + 批准文号 | 没有就不是保健食品，只是普通食品 |

> 表里没有的品类：搜「<品类> 怎么选 关键参数」，或用该品类的国标名去国家标准全文公开系统查强制指标。**通用思路 = 找这个品类「有法定含义的词」和「有强制标准的指标」。**

## 第 3.5 步：标准号事实卡（核实时点：2026-11-07）

判断「商家说的这个词有没有法律含义」时，查这张表。**不要凭印象报标准号，也不要把营销词当标准。**

读表规矩：**「现行」= 今天货架上的货按这版判；「待实施」= 已发布但还没生效，不能拿它判现在的货违规。**「发布」和「实施」是两件事，中间可能隔一两年。

### 食品

| 品类 | 标准号 | 状态 | 关键点 |
|---|---|---|---|
| 灭菌乳（常温纯牛奶） | GB 25190-2010 + 第 1、2 号修改单 | 现行（第 1 号修改单 2025-09-16 已生效） | 灭菌乳只能以生乳为唯一原料，**禁复原乳**；加乳粉的归调制乳，不能叫「纯牛奶」。第 2 号修改单调整的是酸度 |
| 巴氏杀菌乳（冷藏鲜奶） | GB 19645-2010 | 现行 | 仅以生牛（羊）乳为原料，蛋白质 ≥2.9g/100g |
| A2 β-酪蛋白牛奶 | **无强制国标**；T/CNHFA 422-2023 团体标准 | 团标，无强制力 | 团标只约束蛋白质 ≥3.2g/100g。**「A2β ≥0.9g」是认证机构的检测口径，不是团标条款**，更不是国标；「A2」不是品质等级 |

### 报标准号时的六条警戒线

1. **「发布」不等于「生效」。** 说标准时要讲清是哪一天的哪个状态。例：GB/T 18186-2025 是 2025-05-30 **发布**、2026-12-01 才**实施**，现在（2026-11-07）还没生效，不能拿它判现在的货不合规。
2. **别再报已废止的版本**：GB 4706.1-2005、GB 6675-2014、GB 18580-2017、GB 28007-2011。其中家电 2026-08-01 起是 GB 44246-2024。
3. **酱油/食醋现在都还是旧版现行**，说「已废止」是错的——新版只是待实施。同理 GB 7718 / 28050 的 2025 版和总局令 100 号都要等到 2027-03-16。
4. **不要拿「已发布未实施」的新规判旧货**：GB 7916-2026 要 2028-01-01，GB/T 18187-2026 要 2027-09-01。
5. **这些是营销词，没有国标支撑**：A2β-酪蛋白（只有团标，「≥0.9g」是认证口径不是团标条款）、「0 蔗糖」（≠无糖，无糖门槛是糖 ≤0.5g/100g）、「HENF」（无国标，ENF 出自 GB/T 39600-2021）、「GB 18401-2022」（不存在）。
6. **GB 和 GB/T 效力不同**：GB 是强制，GB/T 是推荐、企业可以不执行。说「不符合 GB/T」和法律意义上「不合规」不是一回事。

> 拿不准就**不报标准号**，只说「有强制国标要求，具体号我查一下」——编一个标准号比不报危害大得多。
>
> **表里的日期是核实时点 2026-11-07 的快照。** 隔了一段时间再用，先 `date` 确认今天几号，或重新查一遍；别把「还有 24 天生效」说成「已经生效」。

## 第 4 步：算真实到手价

页面价格 ≠ 你付的钱。逐项算：

```
真实到手价 = 标价
           − 平台券 − 店铺券 − 满减 − 首单/新人优惠
           + 运费 + 上楼费 + 安装费 + 延保费
再除以实际可用数量 → 单位价（每 100g / 每片 / 每次使用）
```

- **单位价才是可比的**。大包装看着贵，单位价常更便宜；但短保食品买大包装会浪费。
- 券门槛注意：「满 99 减 20」是为了让你凑单，不买不需要的东西。
- 首件优惠 / 新人价往往只限一件，第二件回归原价，**别按均价算**。
- 到手价要写清「前提条件」（要领券 / 要凑单 / 限一件），否则用户按原价买会失望。

## 第 5 步：识别营销话术

看到这些词先降权，去找**可验证的东西**：

| 话术 | 真相 |
|---|---|
| 「食品级」「医用级」 | 多数没有标准定义，看具体执行标准和检测报告 |
| 「0 添加」「无添加」 | 只说明没加某几类，不代表没糖没盐；「0 蔗糖」≠「无糖」 |
| 「纯天然」「原生态」 | 无强制标准，基本等于没说 |
| 「A2」「有机」「进口奶源」 | 要看是国标、团标还是企业自说，看认证证书编号 |
| 「原价 ¥999 现价 ¥99」 | 划线价常是虚的，看历史价格/其他平台 |
| 「已售 10 万+」 | 可能是累计单量含刷单，要配合评价数看 |
| 「专利配方」「独家技术」 | 索要专利号，能查 |
| 「工厂直发」 | 看店铺资质是个人店还是企业店 |

**通用动作**：把形容词换成**名词 + 数字 + 编号**。「高品质纯棉」→「100% 棉，执行标准 GB/T xxxx，B 类」。

## 第 6 步：给结论

固定输出结构（用户扫一眼就能决策）：

```
推荐：<商品名>，<到手价>，<单位价>
理由：<2～3 条，每条带出处>
风险：<1～2 条，说明什么情况下别买>
备选：<另一个方案 + 差异一句话>
没查到：<哪项信息缺失，我做了什么（问客服/翻详情），结果如何>
```

**「没查到」这一段必须写，不许省略。** 用户要看到你尽力了，也要知道决策依据的边界在哪。

推荐时遵循：
- 预算内 **性价比拐点** 优先，不是最便宜也不是最贵。
- 有明显硬伤（三无、无 3C、无备案、等级不够）的，**无论多便宜都不推**。
- 差价 < 10% 时选**售后和发货更稳**的那个。

## 第 7 步：把结论画出来（通用，任何品类都能套）

**先定「可比单位」，再选图。** 品类不同，比的轴不一样，别照搬上一个品类的图。

**固定画两张：第一张比价格，第二张比差异。** 只画一张等于只回答了「谁便宜」，没回答「凭什么买它 / 便宜的那款有没有坑」。

| 品类 | 可比单位 | 第一张（价格） | 第二张（差异） |
|---|---|---|---|
| 食品 / 饮品 | 每 100g / 每 100ml / 每份 | `chart` hbar 排单位价 | `compare` 配料 / 蛋白质 / 认证 |
| 生鲜 | 每斤（算上损耗率） | `chart` hbar | `compare` 新鲜度 / 产地 / 发货时效 |
| 电器 / 3C | 总价 + 额定功率 / 容量 / 年电费 | `metric` 到手价 + 年电费 | `compare` 逐项对参数 |
| 服装 / 纺织 | 单件价 + 面料成分 + 安全类别 | `chart` hbar 单件价 | `compare` 面料 / 安全类别 / 版型 |
| 化妆品 / 日化 | 每 ml / 每 g（算正装不是小样） | `chart` hbar | `compare` 成分 / 备案号 / 容量 |
| 家居 / 建材 | 每平米 / 每张板 / 每延米 | `chart` hbar | `compare` 甲醛等级 / 板材 / 工艺 |
| 母婴用品 | 每片 / 每次（按实际用量） | `chart` hbar | `compare` 安全类别 / 成分 / 认证 |
| 保健 / 宠物 | 每份有效成分含量 | `chart` hbar | `compare` 有效成分 / 配方 |
| 服务 / 会员 | 每月 / 每次使用 | `chart` hbar | `compare` 权益 / 限制条款 |
| 通用兜底 | 到手价 / 单位价 / 关键指标 | `metric` 三连 | `compare` 关键差异 |

**选组件的规矩**：

**结论至少两张图，不是一张。** 一张图只能回答一个问题，用户看完还得自己在脑子里拼。固定用这个组合：

- **第一张（必出）：`chart` kind=`hbar`** —— 排「可比单位」的价格（每升 / 每 100g / 每片 / 每平米）。这是「谁更便宜」，一眼看完。
- **第二张（必出，二选一）**：
  - 候选各有强项、参数不可直接相减 → `compare`，每个候选一块，3～4 行（第一行到手价，后面写差距最大的那几项）
  - 差距主要就是一个数（贵 4 块多 0.7g 蛋白 / 贵 20 块多 2 度电）→ `metric` 2～4 个，把「多花的钱买到什么」直接摆出来
- 只在**确实有第三层信息**（风险、缺证据、坑）时才加第三个视图，例如 `callout` tone=`warn` 顶出「便宜的那款是限 1 件，第二箱回原价」。

其它规矩：

- 2～4 个候选横评 → `compare`，每项 3～4 行，第一行写到手价
- 同一个量在不同候选间比大小 → `chart` kind=`hbar`（手机上横条比竖条好读，类别名不会被截断）
- 只有几个关键数字 → `metric`，超过 4 个就换 `compare`
- 查证有先后 / 有进度 → `steps`
- 有风险要单独顶出来 → `callout` tone=`warn`
- 参数多、要逐项对齐 → `table`，≤8 列
- **能一句话说清的小结论别画**：单个数字、普通列表、闲聊都不画。但**主结论不许只画一张就收工**。
- 一条回复**最多两个视图**（第三层风险信息用 callout 文字顶，不占视图名额），围栏 JSON ≤4KB；数据必须真实，估算值写进 `caption`
- 每个图都要带**单位和口径**（「按券后到手价 ÷ 总毫升数，X 月 X 日实时价」），没单位和出处的图等于装饰
- 两张图**不许画同一组数字**：第一张比价格，第二张就必须比别的（参数 / 差值 / 风险），否则就是重复。

**反例（别这么干）**：

1. 给牛奶画了「每升单价」，下一个买电视也画「每升单价」——轴错了，电视比的是功率、尺寸、能效。
2. 同一组数字先文字讲一遍、再表格摆一遍、再图表画一遍——重复三次，不如只留一张图。
3. 图里只有相对长度没有数值标签——读者没法验证，不如不给。
4. 拿平台标价当纵轴——页面价不是你付的钱，先算到手价。
5. **整条回复只画一张价格横条就收工**——用户知道谁最便宜了，但不知道「贵的那款值不值」「便宜的有没有坑」。价格图 + 一张差异图是底线。
6. **第二张图把第一张的数字又画一遍**（比如横条画完再画个柱状图）——换汤不换药，等于只画了一张。

## 手机实操要点

用 `mcp__phone__*` 操作手机时：

- **先看屏幕再动手**：`screen` 拿到元素编号，编号只在本屏有效。点错了往往直接跳出 App。
- **优先点页面上的按钮，别点键盘区**：键盘上的索引容易失手回到桌面。
- **搜索流程**：首页搜索框 → `tap` 输入框 → `type` 关键词（可能需要 `submit: true`）→ `tap` 页面上的「搜索」按钮。
- **结果页只用第一屏**：`screen` 一次就够，读出来的编号里挑 3～5 个候选，**不要 `scroll` 找更多**。确实凑不出 3 个才 `scroll` 一次，滑完立刻选。
- **`collect` 只用来读详情页，不用来刷结果页**：结果页刷多了就是在浪费用户时间。
- **点进商品后先 `screen` 记下参数卡，再决定滑不滑**：参数卡就能筛掉一半，不值得为一个明显不合适的商品滑 20 屏。
- **详情页往下滑有上限**：`scroll(screen, "down")` 直到出现「商品详情」结束提示或「已经到底了」，**最多 6 次**。滑完还没看到产品信息块，直接转客服问，别硬翻。
- **图片看不清**：`screen(image: true)` 拿带标号截图，再用 `read_image` / 调整看大图。
- **客服流程**：`tap` 底部「客服」→ `screen` 找输入框 → `type` 问题 → 有时还要再 `tap` 一次「发送」→ **过一会儿回来 `screen` 看回复**。
- **登录/验证码/支付**：一律 `handoff`，别自己点。

## 反面案例（真实踩过的坑，别重复）

1. 只看了参数卡（生产日期、蛋白质含量、保质期），发现没有配料表就断定「查不到」并退出 → **错**。配料表在详情长图的产品信息块里，也问客服能拿到。
2. 问了客服「有配料表吗」得到「没有」就放弃 → **错**。换个问法要「包装背面实拍图」，拿到了。
3. 客服回复了却没回去看 → **错**。发完问题要主动回来收结果。
4. 拿「已售 10 万+」当质量证明 → **错**。要交叉看评价数、追评、问大家。
5. 用页面标价直接比价，没算券和运费 → **错**。到手价才算数。

## 快速执行清单

动手前默念一遍：

- [ ] **平台确认了吗？**（用户点名就跳过；没点名先问一句）
- [ ] 需求五问补全了吗？（用途/硬约束/可妥协/数量/失败代价）
- [ ] 至少 3 个候选，覆盖三个价位段了吗？**是不是只在第一屏选的（最多滑一次）？**
- [ ] **选完先把候选池一句话报给用户了吗**（给否决权，别闷头查完才说）？
- [ ] 每个候选的**信息缺口清单**列了吗？
- [ ] 缺口一列出来，**客服问题先发出去了吗**（先发商品卡片，别等，边翻边等）？
- [ ] 详情长图翻到最后几张了吗（尤其倒数 1～3 张）？**但滚动次数没超过 6 次吧？**
- [ ] 客服回复回访了吗？缺口补上了吗？
- [ ] 品类关键参数逐项核验了吗？
- [ ] 到手价和单位价算了吗？前提条件写了吗？
- [ ] 有没有踩营销话术坑？形容词换成数值编号了吗？
- [ ] 结论里「没查到」那段写了吗？每条理由是都带出处吗？
- [ ] **画够两张了吗？** 第一张比价格（hbar），第二张比差异（compare / metric），没画成同一组数字？
- [ ] 可比单位先定了吗？图带单位和口径了吗？
